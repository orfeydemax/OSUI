# Правила загрузки контекста (V8 OSUI §23)

> Трёхуровневая система «ленивой» подгрузки контекста.
> Цель — минимум токенов при максимальной полноте информации.

---

## 🔴 HOT — читается ВСЕГДА при старте любой задачи

| Файл | Зачем читать |
|------|--------------|
| `PROJECT_BRAIN.yaml` | Сжатое полное знание проекта: стек, агенты, текущий статус, ключевые решения |

**Бюджет:** ~1 500 токенов

---

## 🟡 WARM — читается при задачах с кодом

| Файл | Зачем читать |
|------|--------------|
| `git log --oneline -n 10` | Текущее состояние репозитория |
| `docs/CHANGELOG.md` | История изменений и решений |
| Целевой файл кода | Только тот, который нужно редактировать |

**Бюджет:** +1 000–5 000 токенов

---

## 🔵 COLD — читается ТОЛЬКО при Extended/Critical треках или по явному запросу

| Файл | Зачем читать |
|------|--------------|
| `.agent/ARCHITECTURE.md` | Полная архитектура системы |
| `.agent/agents/{agent}.md` | Файл конкретного агента |
| `.agent/skills/{skill}/SKILL.md` | Конкретный навык |
| `.agent/workflows/{workflow}.md` | Конкретный воркфлоу |
| `docs/change_card.yaml` | Карточка изменения |

**Бюджет:** +5 000–30 000 токенов

---

## Бюджет по типу задачи

| Тип задачи | Уровни | Токены |
|------------|--------|--------|
| Question / Survey | 🔴 Hot | ~10 000 |
| Nano / Core | 🔴 Hot + 🟡 Warm | ~11 000–15 000 |
| Extended | 🔴 Hot + 🟡 Warm + 🔵 Cold | ~20 000–40 000 |
| Critical | Все три (полный Cold) | ~40 000–60 000 |

---

## ❌ Жёсткие запреты

- **`docs/Done/`** — никогда не читать целиком (~300 000 токенов, ЗАПРЕЩЕНО).
  Нужна история? → Читать `docs/CHANGELOG.md`
- **`ARCHITECTURE.md`** — не читать для Nano/Core задач. Вся нужная информация уже есть в `PROJECT_BRAIN.yaml`
- **Agent `.md` файлы** — не читать, если задача не требует смены агента
- **Skill `SKILL.md`** — не читать «на всякий случай», только при реальной необходимости
- **Workflow `.md`** — не читать, если пользователь не вызвал slash-команду

---

## Обязательный порядок чтения при старте задачи

1. `PROJECT_BRAIN.yaml` — сжатое полное знание проекта (ВСЕГДА)
2. `git log --oneline -n 10` — текущий статус репо (при работе с кодом)
3. Целевой файл кода — только тот, который нужно менять
4. `docs/CHANGELOG.md` — только если нужна история решений
5. Cold-источники — только если п.1–4 недостаточно

---

> **Главный принцип:** `PROJECT_BRAIN.yaml` — единственный обязательный файл на старте.
> Всё остальное подгружается лениво, только когда реально нужно.
