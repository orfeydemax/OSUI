# Правила загрузки контекста (V9.1 OSUI §23)

> Четырёхуровневая система «ленивой» подгрузки контекста.
> Цель — минимум токенов при максимальной полноте информации.

---

## 🔴 HOT — читается ВСЕГДА при старте любой задачи

| Файл | Зачем читать |
|------|--------------|
| `PROJECT_BRAIN.yaml` | Сжатое полное знание проекта: стек, агенты, текущий статус, ключевые решения |

**Бюджет:** ~1 500 токенов

---

## 🟡 WARM — читается при задачах с кодом (Nano / Core)

| Файл | Зачем читать |
|------|--------------|
| `git log --oneline -n 10` | Текущее состояние репозитория |
| `docs/CHANGELOG.md` | История завершённых CHG |
| Целевой файл кода | Только тот, который нужно редактировать |

**Бюджет:** +1 000–5 000 токенов

---

## 🟠 WARM-ENHANCE — читается при brownfield `/enhance`

> ДОБАВЛЕНО v9.1. Обязательный уровень для ЛЮБОГО `/enhance` изменения.
> Без Warm-Enhance нельзя стартовать `/build` для enhance.

| Файл | Зачем читать |
|------|--------------|
| `docs/00_Registry/PRODUCT_SURFACE_STATE.yaml` | Карта текущего состояния всех surface |
| `docs/00_Registry/SITE_HISTORY_LOG.md` | Реальные события (инциденты, откаты), не только CHG |
| `docs/00_Registry/HARNESS_CAPABILITIES.yaml` | Какие harness-capability доступны для этого change |
| `docs/_templates/current_reality_snapshot.yaml` → заполнить | Снимок as-is состояния затронутых модулей |
| `docs/_templates/protected_behavior_contract.md` → заполнить | Перечень поведений, которые НЕ должны сломаться |
| Затронутые модули (code) | Код, который меняется + соседние shared zones |
| Релевантный human gate trace | Предыдущие решения по этой зоне |

**Бюджет:** +3 000–8 000 токенов

**Обязательные стопы Warm-Enhance:**
- Без baseline (PRODUCT_SURFACE_STATE missing) → **STOP**
- Без protected behavior contract для shared zones → **нельзя переходить к build**
- Без removal handling → **нельзя выполнять destructive delta**
- Без surface history → **нельзя утверждать confidence**

---

## 🔵 COLD — читается ТОЛЬКО при Extended/Critical треках или по явному запросу

| Файл | Зачем читать |
|------|--------------|
| `.agent/ARCHITECTURE.md` | Полная архитектура системы |
| `.agent/agents/{agent}.md` | Файл конкретного агента |
| `.agent/skills/{skill}/SKILL.md` | Конкретный навык |
| `.agent/workflows/{workflow}.md` | Конкретный воркфлоу |
| `docs/Done/{CHG-ID}/change_card.yaml` | Карточка конкретного завершённого CHG |

**Бюджет:** +5 000–30 000 токенов

---

## Бюджет по типу задачи

| Тип задачи | Уровни | Токены |
|------------|--------|--------|
| Question / Survey | 🔴 Hot | ~10 000 |
| Nano / Core | 🔴 Hot + 🟡 Warm | ~11 000–15 000 |
| Enhance (brownfield) | 🔴 Hot + 🟡 Warm + 🟠 Warm-Enhance | ~15 000–25 000 |
| Extended | 🔴 Hot + 🟡 Warm + 🟠 Warm-Enhance + 🔵 Cold | ~20 000–40 000 |
| Critical | Все четыре (полный Cold) | ~40 000–60 000 |

---

## ❌ Жёсткие запреты

- **`docs/Done/`** — никогда не читать целиком (~300 000 токенов, ЗАПРЕЩЕНО).
  Нужна история? → Читать `docs/CHANGELOG.md`
- **`ARCHITECTURE.md`** — не читать для Nano/Core задач. Вся нужная информация уже есть в `PROJECT_BRAIN.yaml`
- **Agent `.md` файлы** — не читать, если задача не требует смены агента
- **Skill `SKILL.md`** — не читать «на всякий случай», только при реальной необходимости
- **Workflow `.md`** — не читать, если пользователь не вызвал slash-команду
- **CHANGELOG.md** — НЕ считать полной памятью. CHANGELOG = завершённые CHG. Реальная история → `SITE_HISTORY_LOG.md` (v9.1)
- **Brownfield `/enhance` без Warm-Enhance** — ЗАПРЕЩЕНО. Нельзя стартовать enhance только по Hot + target file (v9.1)

---

## Обязательный порядок чтения при старте задачи

1. `PROJECT_BRAIN.yaml` — сжатое полное знание проекта (ВСЕГДА)
2. `git log --oneline -n 10` — текущий статус репо (при работе с кодом)
3. Целевой файл кода — только тот, который нужно менять
4. `docs/CHANGELOG.md` — только если нужна история решений
5. **Если `/enhance`:** Warm-Enhance уровень обязателен (см. выше)
6. Cold-источники — только если п.1–5 недостаточно

---

> **Главный принцип:** `PROJECT_BRAIN.yaml` — единственный обязательный файл на старте.
> Warm-Enhance — обязательный уровень для brownfield `/enhance`.
> Всё остальное подгружается лениво, только когда реально нужно.
