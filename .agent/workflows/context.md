# /context — Формализованная ленивая подгрузка контекста

> V9.1 Lifecycle Stage: **Управление токеновым бюджетом и масштабированием понимания ИИ**
> Reference: GEMINI.md (§23), docs/context-loading-rules.md

## Назначение
Обеспечить ИИ-агентам контролируемый механизм погружения в документацию без сканирования излишних данных. Снижает затраты на токены в 3-6 раз, предотвращает переполнение контекста.

## Четырёхуровневая система загрузки (Контракт /context)

### Уровень 1: 🔴 Hot Load (До 1 500 токенов)
**Вызов:** `/context hot` (или читается автоматически при старте сессии)
- **Цель:** Базовое понимание, о чем проект, какой стек и какие основные архитектурные решения.
- **Действия:**
  1. Прочитать `PROJECT_BRAIN.yaml`.
  2. Прочитать `GEMINI.md` (выполняется автоматически благодаря системному промпту).

### Уровень 2: 🟡 Warm Load (До 5 000 токенов)
**Вызов:** `/context warm`
- **Цель:** Изучение текущей обстановки для написания кода (Nano / Core треки).
- **Действия:**
  1. Выполнить `git log --oneline -n 10`
  2. Прочитать `docs/CHANGELOG.md`
  3. Прочитать целевой файл кода, в котором планируются правки.

### Уровень 2.5: 🟠 Warm-Enhance Load (До 8 000 токенов)
**Вызов:** `/context warm-enhance`
- **Цель:** Подготовка к brownfield `/enhance` — чтение baseline, protected behaviors, surface state, событий системы.
- **Обязательность:** Вызывается АВТОМАТИЧЕСКИ при любом `/enhance`, не требует ручного вызова.
- **Действия:**
  1. Прочитать `docs/00_Registry/PRODUCT_SURFACE_STATE.yaml` — карта текущих surface
  2. Прочитать `docs/00_Registry/SITE_HISTORY_LOG.md` — реальные события (откаты, инциденты)
  3. Прочитать `docs/00_Registry/HARNESS_CAPABILITIES.yaml` — доступные harness capabilities
  4. Заполнить `docs/_templates/current_reality_snapshot.yaml` — снимок as-is
  5. Заполнить `docs/_templates/protected_behavior_contract.md` — что НЕ должно сломаться
  6. Прочитать затронутые модули (code) + соседние shared zones
  7. Проверить релевантные human gate traces

**Обязательные стопы:**
- `PRODUCT_SURFACE_STATE.yaml` missing → **STOP. Нельзя продолжать enhance.**
- Protected behavior contract не заполнен для shared zones → **STOP. Нельзя переходить к build.**
- Removal detected → **заполнить `removal_delta.md`, эскалировать до Extended+**

### Уровень 3: 🔵 Cold Load (До 30 000 токенов)
**Вызов:** `/context cold [цель]`
- **Цель:** Глубокая архитектурная работа, рефакторинг, изучение истории (Extended / Critical треки).
- **Действия:** (только запрошенные элементы)
  1. Чтение `ARCHITECTURE.md`
  2. Чтение конкретных правил из `.agent/skills/{skill}/SKILL.md`
  3. Чтение исторической карточки `docs/Done/{CHG-ID}/change_card.yaml` (только нужный ID).

## Жесткие запреты (Forbidden)
- ❌ **ЗАПРЕЩЕНО** сканировать или читать `docs/Done/` целиком.
- ❌ **ЗАПРЕЩЕНО** загружать `ARCHITECTURE.md` для микро-фиксов (Nano-трек).
- ❌ **ЗАПРЕЩЕНО** читать весь список файлов из `.agent/workflows/` "в надежде найти нужный". Названия и описания есть в системном каталоге.
- ❌ **ЗАПРЕЩЕНО** стартовать `/enhance` без Warm-Enhance уровня. Hot + target file — недостаточно для brownfield. (v9.1)
- ❌ **ЗАПРЕЩЕНО** считать `CHANGELOG.md` полной памятью системы. CHANGELOG = завершённые CHG. Реальная история → `SITE_HISTORY_LOG.md`. (v9.1)

## Использование в чате
Пользователь может просто написать:
- `Используй /context warm` — Hot + Warm
- `Используй /context warm-enhance` — Hot + Warm + Warm-Enhance
- `Используй /context cold архитектура` — полный контекст

И ИИ обязан немедленно прекратить чтение глобальных спецификаций и сфокусироваться на указанных уровнях.
